# Implementation Plan: WSL Development Environment Alignment

**Branch**: `009-wsl-dev-env-alignment` | **Date**: 2026-05-16 | **Spec**: [spec.md](./spec.md)

**Note**: Filled by `/speckit-plan`. Spec is settled (2 Clarifications + 1 binding Policy resolved 2026-05-16; FR-002 direction pinned by direct diff inspection). This plan adds research, data-model, contracts, quickstart — and an explicit Constitution Check that gates the implementation phase.

## Summary

Primary requirement: make WSL2 bash a fully usable primary development environment for this Spec-Kit-extension repo, after a Windows→WSL migration that left a maintainer unable to (a) run any `tests/*.ps1` (no `pwsh` in WSL), (b) execute several `/speckit-*` slash commands that hardcode `.specify/scripts/powershell/` paths, and (c) work with a clean `git status` (`.gitattributes` / `.gitignore` show a 81+/81− phantom diff that is pure CRLF→LF normalization).

Technical approach: implement FR-001..FR-015 as **four sequential phases that touch ONLY configuration and dev-internal surfaces** — no bridge runtime changes, no new extensions, no new vendor-managed skills. The lever is the Policy resolved in Clarifications: dev-environment-only artifacts collapse to bash and drop PowerShell entirely (Phase B ports `tests/*.ps1` → `tests/*.sh` and deletes the originals); user-facing install-state artifacts (`.specify/scripts/`, vendor-managed `.claude/skills/speckit-{non-bridge}/`, `.agents/skills/speckit-{non-bridge}/`) get gitignored and regenerated per-developer via a one-line `specify init --here --script <flavor>` bootstrap documented in `AGENTS.md`. The project-owned `speckit-superpowers-bridge` skill files stay committed because they ARE the project's deliverable. Verification (FR-013) is one full bridge end-to-end cycle from WSL bash, captured as a committed `verification.md`.

## Implementation strategy (phased)

Phases are sequential because each builds on prior state. The single-developer scope means parallelism inside a phase has no leverage; sequential ordering also makes the FR-013 verification cycle a natural Phase D capstone.

1. **Phase A — Working-tree hygiene + install-state un-indexing (US2, P1)**:
   - Commit the LF-normalized `.gitattributes` + `.gitignore` (FR-002).
   - Add `.specify/scripts/` and the seven non-bridge vendor-managed skill paths (both `.claude/skills/speckit-*/` and `.agents/skills/speckit-*/`) to `.gitignore` (FR-005 + FR-005b).
   - `git rm -r --cached` the now-ignored directories so the index matches the new policy.
   - Flip `.specify/init-options.json.script` from `"ps"` to `"sh"` (FR-005).
   - Run `specify init --here --script sh` once to regenerate the now-gitignored content locally (bash flavor for the maintainer's WSL host).
   - Verify: `git status` clean on WSL bash, SC-002 + SC-005 + SC-006 all green.

2. **Phase B — Test suite port + .ps1 deletion (US1 part 1, FR-007)**:
   - Port the four tests in order of complexity (simplest first):
     1. `test-handoff-shape.ps1` → `test-handoff-shape.sh` (pure JSON shape lint; `jq` replaces `ConvertFrom-Json`).
     2. `test-guard-hardcoded-rules.ps1` → `test-guard-hardcoded-rules.sh` (drive `guard-command.sh` with fixture states, assert allow/deny).
     3. `test-bridge-state-summary.ps1` → `test-bridge-state-summary.sh` (parse `[bridge state]` block from stdout).
     4. `test-claude-codex-skill-parity.ps1` → `test-claude-codex-skill-parity.sh` (cross-agent file-content parity — most complex; preserve assertion semantics).
   - For each port: prove green on WSL bash before deleting the `.ps1` original. No `.ps1` test files remain at the end of this phase.
   - Add `tests/run-all.sh` (or equivalent documented loop) so SC-001 has a single entrypoint.

3. **Phase C — Docs alignment (US3, FR-010 + FR-005a + FR-011)**:
   - Add a "Supported host environments" section to `AGENTS.md` listing: Windows PowerShell 5.1+ (prereqs: `git`, `pwsh`, `gh`, `jq`); WSL bash 5.2+ (prereqs: `git`, `bash`, `gh`, `jq`, `specify` CLI 0.8.10+).
   - Document the one-line bootstrap: `specify init --here --script sh` (or `--script ps` on Windows).
   - State the documented default flavor and confirm consistency with `init-options.json` (FR-011).
   - Confirm SC-004 reachability ("a new contributor can answer in < 30s").

4. **Phase D — Full bridge end-to-end verification (FR-013 + FR-015 + SC-003)**:
   - From WSL bash, execute the cycle on this feature (009): `/speckit-tasks` (consuming this plan) → bridge handoff via the after_tasks mandatory hook → bridge orchestration of tasks.md → `update-handoff complete`. Each step logs `[bridge state]` summary block (FR-009 fully exercised by Phase A's `specify init` regen of vendor-managed skill files).
   - Capture transcripts to `specs/009-wsl-dev-env-alignment/verification.md` with host environment (`uname -a`, `bash --version`, `jq --version`, `gh --version`, `git --version`) plus the slash commands invoked plus the resulting state-summary blocks.
   - Confirm SC-003 + FR-015 satisfied.

## Open research items (Phase 0 inputs)

These are pinned to research.md so they're answered before Phase A:

- **R1**: When `specify init --here --script sh` runs against this repo with an existing `init-options.json` set to `script=ps`, does the CLI (a) overwrite `init-options.json` silently, (b) refuse without `--force`, or (c) merge fields? Phase A's flip-then-init sequence depends on the answer; if (b), we flip the file ourselves first, then init; if (a), we set the field via init's flag and let it write.
- **R2**: What exactly does `specify init --here --script <flavor>` regenerate on an existing repo? Confirm the inclusion list (`.specify/scripts/<flavor>/...`, the seven non-bridge vendor-managed slash-command skills in `.claude/skills/` and `.agents/skills/`) and the exclusion list (must NOT touch `.specify/extensions/`, `.specify/templates/`, the project-owned `speckit-superpowers-bridge` skill files, `AGENTS.md`, `CLAUDE.md`, `.specify/extensions.yml`, `.specify/superpowers-handoff.json`). The contract emitted in `contracts/bootstrap-contract.md` derives from this answer.
- **R3**: Bash idiom inventory for the four test ports: which combination of `jq`, `grep -E`, `awk`, `mapfile`, process substitution is the cleanest replacement for each PowerShell construct used in the originals (`ConvertFrom-Json`, `Where-Object`, `Select-String`, `Compare-Object`, `Get-FileHash`, etc.)? Output goes to `contracts/tests-bash-port-contract.md`.
- **R4**: Current `AGENTS.md` already has a section on "Primary Design Reference" and master cross-agent guidance. Where exactly to insert the "Supported host environments" section so it's discoverable in < 30s (SC-004) without breaking the existing structure? Likely near the top, alongside the agent-routing notes.
- **R5**: Are there any places in the project that reference `tests/*.ps1` BY NAME (CI scripts, `scripts/release/validate-release-readiness.ps1`, `marketplace/README.md`, etc.) that need to be redirected to `tests/*.sh` after Phase B? A grep pass during Phase 0 surfaces them so Phase B can update them in the same commit set.

## Out of Plan

These were considered and explicitly NOT planned for this feature:

- A release tag / `extension.yml` bump — this is a dev-env alignment, not a release.
- macOS bash sandbox row — deferred until macOS becomes a maintainer's primary host.
- Installing `pwsh` in WSL — rejected by Q1+Q2 Policy ("dev-environment-only artifacts collapse to bash").
- Building a flavor-agnostic test runner that auto-dispatches `.ps1` vs `.sh` — rejected per Q1+Q2 Policy (tests are dev-internal; the policy is "drop PowerShell entirely" for dev-internal artifacts, so the dispatcher would be dead weight).
- Inline `--no-pwsh-fallback` flags or environment shims in bridge runtime — rejected per FR-014 (bridge runtime byte-stable).
- Editing the vendor-managed `.claude/skills/speckit-*` files to swap `powershell/` for `bash/` paths by hand — rejected per Principle V; the `specify init` regen path achieves the same outcome without the prohibited edit.
- Bootstrap automation (a `Makefile` or `setup.sh` wrapper around `specify init`) — rejected per "Lightweight & Repo-Local"; one documented command is enough.
- Reverting the `.gitattributes`/`.gitignore` LF normalization — rejected by FR-002 + Assumptions (the diff is verified pure CRLF→LF, no semantic change, and `.gitattributes` self-declares `*.sh text eol=lf`).
