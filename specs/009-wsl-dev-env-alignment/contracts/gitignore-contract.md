# Contract: `.gitignore` Surface After This Feature

**Feature**: `009-wsl-dev-env-alignment` | **Plan**: [../plan.md](../plan.md) | **Data model**: [../data-model.md Entity 2](../data-model.md#entity-2-gitignore-the-install-state-boundary)

This contract enumerates exactly which paths are added to `.gitignore` by this feature, the rationale per path, and what each path's git-index state MUST be after Phase A. The contract is binding on `tasks.md` — no task may add to or subtract from this list without a spec amendment.

## Index operations performed by Phase A

For each new ignored path, Phase A runs:

```bash
git rm -r --cached <path>
```

This removes the path from the index without deleting the on-disk content (so `specify init` can later regenerate it idempotently without a destructive intermediate state).

## Non-additions (explicitly NOT ignored by this feature)

Per the Policy, future install-state surfaces (e.g., `.specify/integrations/*.manifest.json`) MAY be ignored under the same Policy in subsequent features, but this feature deliberately does NOT enumerate them — they are outside Phase A's blast radius and are caught by the Policy's binding language in spec Clarifications.

The following are explicitly NOT added to `.gitignore` by this feature despite being adjacent to install-state:

- `.specify/integrations/codex.manifest.json` — would qualify under the Policy, but is out of FR-014's scope; treated as a follow-up.
- `.specify/extensions/.cache/`, `.specify/extensions/.registry`, `.specify/workflows/...` — already gitignored in `.gitignore` since v0.4.2; this feature does not duplicate them.

## Failure handling

If after Phase A any "empty" check returns non-empty, the `git rm -r --cached` step did not fully clean the index. Recovery: re-run the `git rm -r --cached <path>` for the offending path, commit, re-validate.

If after Phase A any "NON-empty" check returns empty, a project-deliverable file was accidentally untracked. Recovery: `git checkout HEAD~1 -- <path>` to restore from prior commit; verify the `.gitignore` rule does NOT match the deliverable; re-validate.
