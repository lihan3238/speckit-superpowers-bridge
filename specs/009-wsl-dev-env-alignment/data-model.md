# Phase 1 Data Model: WSL Development Environment Alignment

**Feature**: `009-wsl-dev-env-alignment` | **Date**: 2026-05-16 | **Plan**: [plan.md](./plan.md)

This feature has no application data model — it's an infrastructure alignment. The "entities" here are **configuration-state shapes** and the **file-trust matrix** that describes which paths are owned by which side (project / Spec Kit install / developer-local). This file enumerates them so contracts and tasks can reference them by name.

---

## Entity 1: `.specify/init-options.json` (the script-flavor pointer)

**Purpose**: Records the developer's chosen Spec Kit flavor and integration. Read by every `/speckit-*` slash command via the vendor-managed `SKILL.md` files to dispatch the correct flavor of `.specify/scripts/`.

**Schema** (relevant subset):

| Field | Type | Before (in repo as of 008) | After (this feature) | Notes |
|---|---|---|---|---|
| `ai` | string | `"codex"` | unchanged | Untouched by this feature; the actor's identity is orthogonal to the script flavor. |
| `ai_skills` | bool | `true` | unchanged | Same as above. |
| `branch_numbering` | string | `"sequential"` | unchanged | Numbering policy is orthogonal. |
| `context_file` | string | `"AGENTS.md"` | unchanged | The "AGENTS.md is master" decision is enshrined elsewhere (CLAUDE.md). |
| `here` | bool | `true` | unchanged | `--here` install marker. |
| `integration` | string | `"codex"` | unchanged | Integration choice is orthogonal to script flavor. |
| **`script`** | **string** | **`"ps"`** | **`"sh"`** | **THIS FEATURE: the only field that changes.** |
| `speckit_version` | string | `"0.8.10"` | possibly bumped to `"0.8.11"` by `specify init` regen | If `specify init` rewrites this field as a side effect, accept the bump (we have 0.8.11 installed) and record in CHANGELOG. |

**Validation**:

- `script` MUST be exactly `"sh"` after Phase A.
- All other fields MUST be byte-identical before/after EXCEPT `speckit_version` which MAY bump per `specify init` behavior (see R2).
- File MUST be valid JSON parseable by both `jq` and PowerShell `ConvertFrom-Json` (both flavors of slash commands read it).

**Lifecycle**: The file is tracked in git; the change is a single one-field PATCH commit.

## Entity 2: `.gitignore` (the install-state boundary)

**Purpose**: Declares which paths git ignores. This feature expands the ignore-list to cover all "install-time generated state" per the Policy in spec Clarifications.

**Schema**: Plain-text glob list, one entry per line, with comment headers. Existing comment-block structure MUST be preserved.

**New entries added by this feature** (under a new comment block titled `# Spec Kit install-time generated state (009: WSL alignment)`):

```text
# ─────────────────────────────────────────────────────────────────────────────
# Spec Kit install-time generated state (009 v0.5.x WSL alignment)
# Each developer regenerates these locally via:
#   specify init --here --script <ps|sh> --force
# See AGENTS.md "Supported Host Environments" for bootstrap details.
# ─────────────────────────────────────────────────────────────────────────────
.specify/scripts/

# Vendor-managed slash-command skill files (regenerated by `specify init`).
# The project-owned `speckit-superpowers-bridge` skill is EXCLUDED — it stays tracked.
.claude/skills/speckit-analyze/
.claude/skills/speckit-checklist/
.claude/skills/speckit-clarify/
.claude/skills/speckit-implement/
.claude/skills/speckit-plan/
.claude/skills/speckit-tasks/
.claude/skills/speckit-taskstoissues/
.agents/skills/speckit-analyze/
.agents/skills/speckit-checklist/
.agents/skills/speckit-clarify/
.agents/skills/speckit-implement/
.agents/skills/speckit-plan/
.agents/skills/speckit-tasks/
.agents/skills/speckit-taskstoissues/
```

**Validation**:

- After Phase A, `git status --ignored` MUST list each of the above paths under "Ignored files".
- After Phase A, `git ls-files .specify/scripts/ .claude/skills/speckit-analyze/ ...` (for each new ignore) MUST return zero output (file un-indexed).
- `.claude/skills/speckit-superpowers-bridge/` and `.agents/skills/speckit-superpowers-bridge/` MUST still appear in `git ls-files`.

**Lifecycle**: One commit per logical block (the LF normalization commit per FR-002 is separate from this scope expansion).

## Entity 3: `.gitattributes` (the line-ending policy)

**Purpose**: Declares per-pattern line-ending rules. Existing content is correct; this feature only normalizes its OWN file bytes from CRLF to LF (the 81+/81− diff verified in spec FR-002).

**Schema**: Content is byte-identical before/after EXCEPT each line loses its trailing `\r`. No semantic change.

**Validation**:

- `file .gitattributes` MUST report `ASCII text` (not `ASCII text, with CRLF line terminators`).
- Same check on `.gitignore`.
- `git diff` MUST report no remaining changes to either file after the LF normalization commit.

## Entity 4: Bash test files (`tests/test-*.sh`)

**Purpose**: Replace the four existing `tests/test-*.ps1` with bash equivalents that preserve the same assertion contracts (see `contracts/tests-bash-port-contract.md`).

**Schema** (per file):

| Property | Constraint |
|---|---|
| Shebang | `#!/usr/bin/env bash` |
| Header | `set -euo pipefail` |
| Output on PASS | Final line: `<test-name>-ok (<flavors-exercised>)` matching the existing PS test's final-line convention |
| Output on FAIL | Non-zero exit + diagnostic to stderr |
| Output on SKIP | Explicit `  [skip] <reason>` line in stdout; exit 0 IF every assertion successfully ran-or-skipped (no silent absence per FR-007) |
| Cleanup | `trap` restores any handoff/snapshot files mutated during the test |

**Lifecycle**:

1. Bash port written and committed in the same commit as the `.ps1` deletion.
2. Phase B per-test sequence: write `.sh` → prove green via `bash tests/test-<name>.sh` → `git rm tests/test-<name>.ps1` in the same commit.

## Entity 5: `AGENTS.md` "Supported Host Environments" section

**Purpose**: Documents host prereqs, default flavors, and the FR-005a bootstrap. Content shape pinned by [research.md R4](./research.md#r4--where-to-insert-the-supported-host-environments-section-in-agentsmd).

**Schema**: A new `## Supported Host Environments` H2 section with a 3-column table + bootstrap one-liner + skill-boundary note + test-runner one-liner.

**Validation** (against FR-010 + FR-011 + SC-004):

- The section MUST name both Windows PowerShell 5.1+ and WSL2 bash 5.2+.
- The section MUST list the bootstrap command literally as `specify init --here --script <ps|sh> --force`.
- The section MUST state which flavor matches `init-options.json.script` for each environment.
- A new contributor reading AGENTS.md top-to-bottom MUST encounter the section within the first ~80 lines (SC-004 reachability test).
